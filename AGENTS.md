# AGENTS.md: thrift-api-client

Instructions for coding agents working in this repository. Read this before changing anything.

## What this is

Java 11 libraries for talking to the CREDITS node and contract executor over Apache Thrift, plus the
shared utilities the contract executor is built on (Base58, Blake2s, the `Variant` conversions of
contract arguments, the in-memory Java compiler and source-code parsing used to compile contracts).

Related repositories of [CreditsCommunity](https://github.com/CreditsCommunity):

- `contract-executor`: its build installs this repository's modules (branch
  `build/reproducible-1518`) before building the executor, which uses `executor_client` 1.4 and
  `general` 1.3 from them; `general` 1.2 and `node_client` 1.4 come from artifacts vendored in the
  executor repository (see its `BUILDING.md`).
- `thrift-interface-definitions`: the Thrift IDL (`api.thrift`, `executor.thrift`, `apiexec.thrift`,
  `general.thrift`) the generated code here comes from; the node includes it as a submodule.
- `node`: the server side of the node API; `smart-contract-api`: the other executor dependency.

## Branches: read this first

- **`build/reproducible-1518`** is what the contract executor builds against (its `build.yml` checks
  out this branch): `59d1e9a` plus pins of the Eclipse dependencies to the versions bundled in
  executor build 1518 (`1a8d79f`). Changes meant for the executor go there, then reach `master`
  by a merge.
- `master` (the default branch) is `build/reproducible-1518` merged with the later upstream commits:
  two `node_client` fixes (transaction id, deploy signature), which the executor does not use, and
  AGENTS.md. Its `general` and `executor_client` sources are those of `build/reproducible-1518`.
- `libthrift` stays at 0.12.0. A dependabot bump to 0.14.0 broke the build (0.14 has no module
  named `libthrift`, so `executor_client`'s and `node_client`'s `module-info.java` fail with
  "module not found: libthrift") and was reverted on `master`. Do not merge such a bump: it changes
  what the executor bundles.
- `mvn-repo` holds Maven artifacts published by the original project.

## Platform constraints

Mainnet runs the official node 4.2.532 with executor build 1518, which is built with this code. A
change in what the executor bundles (for example the compiler and argument conversion utilities of
`general`) can change contract results, and is then consensus-relevant. Never change consensus
behaviour unilaterally; executor results must stay identical to 1518.

## Layout

| Path | Contents |
|---|---|
| `general/` | `com.credits.general` 1.3: Thrift types shared by both APIs (`thrift/generated`), crypto (`Blake2S`), `util` (Base58, converters, `variant`, `compiler`, `sourceCode`), pojos, class loading |
| `node_client/` | `node_client` 2.4: the node API client (`service/NodeApiService*`, `NodeThriftApiClient`) and generated code |
| `executor_client/` | `executor_client` 1.4: the executor's API (`ContractExecutor`) and the node API the executor calls back (`apiexec.APIEXEC`), generated |
| `pom.xml` | parent `api-client`, Java 11, `libthrift` version |

Code under `*/thrift/generated` was generated by the Thrift compiler 0.12.0 (see the file headers):
do not edit it by hand; regenerate it from the IDL with the same compiler version.

## Build and test

JDK 11 and Maven. For the executor:

```sh
mvn -B -DskipTests install      # installs general, node_client, executor_client into ~/.m2
mvn -B test                     # JUnit 4 tests in general/src/test
```

JDK 11 is needed: the Lombok version used does not run on JDK 17.

## CI

`.github/workflows/ci.yml`: `mvn -B install` (build and tests) with JDK 11 on every push to
`master` and every pull request. The contract executor's CI also builds `build/reproducible-1518`
and compares every contract result with build 1518.

For a build byte-identical to 1518, use JDK 11.0.3 and the Maven settings of contract-executor
(`third-party/maven-settings.xml` on its branch `build/reproducible-1518`; see its `BUILDING.md`).

## Conventions

- One topic per pull request, against the branch the change is meant for (usually
  `build/reproducible-1518`). Docs, comments and commit messages in English.
- Never `git add -A` or `git add .`: stage explicit paths. Never delete branches after a merge.
- Do not change module versions or dependency versions casually: the executor resolves them by
  version, and newer Eclipse/JDT releases are built for Java 17.

## Pitfalls

- Contract amounts in `sendTransaction` are `double`s. A contract call whose arguments do not match
  the method's declared types (the `Variant` variants) fails, and the fee is still paid.
- On mainnet a contract cannot call another contract (executor 1518 fails every
  `invokeExternalContract`) and no value passes from one contract to another; enabling either needs
  a coordinated, height-gated upgrade of all trusted-capable nodes.
- Test changes by building contract-executor against them; its CI compares every contract result
  with build 1518.
